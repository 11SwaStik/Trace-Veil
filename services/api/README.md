# Traceveil API — Backend Foundation

The FastAPI backend for Traceveil. This is the **foundation** only — the
web server, the database connection, and a place for future features to
plug in. No auth, no attack simulation, no WebSockets, no replay engine
yet — those each become a feature module under `app/modules/` later.

Project-level docs live in [docs/](../../docs/) — read those for product
context. This file is just the developer manual for this service.

---

## What's in here

```
services/api/
├── requirements.txt        # Python packages to install
├── .env.example            # template for environment variables
└── app/
    ├── __init__.py
    ├── main.py             # entry point — FastAPI app + lifespan
    ├── config.py           # reads .env into a Settings object
    ├── database.py         # SQLAlchemy engine, session, Base, init_db
    ├── routes/
    │   ├── __init__.py
    │   └── health.py       # /healthz, /readyz
    └── modules/            # feature modules go here later
        └── __init__.py     # (placeholder, with a note on the pattern)
```

### Role of each file

| File | What it does |
|---|---|
| [requirements.txt](requirements.txt) | List of Python packages. `pip install -r requirements.txt` reads this. |
| [.env.example](.env.example) | Template for secrets/config. Copy to `.env` and fill in. Never commit `.env`. |
| [app/main.py](app/main.py) | Entry point. Builds the FastAPI app, mounts routers, runs `init_db()` on startup. |
| [app/config.py](app/config.py) | Loads `.env` via `python-dotenv` and exposes a `settings` object. |
| [app/database.py](app/database.py) | All DB plumbing — engine, async session, `Base` class, `init_db()`. |
| [app/routes/health.py](app/routes/health.py) | `/healthz` (process alive?) and `/readyz` (DB reachable?). |
| [app/modules/](app/modules/) | Empty placeholder. Each future feature gets its own subfolder. |

## Local setup

### 1. Prerequisites

- Python 3.12+
- PostgreSQL 15+ (locally, in Docker, or via a cloud provider)

### 2. Install Python dependencies

```bash
cd services/api

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

### 3. Configure environment

```bash
cp .env.example .env
# open .env and adjust DATABASE_URL if your Postgres differs
```

### 4. Run Postgres

The fastest path is Docker:

```bash
docker run -d --name traceveil-postgres \
  -e POSTGRES_USER=traceveil \
  -e POSTGRES_PASSWORD=traceveil \
  -e POSTGRES_DB=traceveil \
  -p 5432:5432 \
  postgres:16-alpine
```

(If you have Postgres installed natively, just create the user + DB
manually and update `DATABASE_URL` in `.env`.)

### 5. Run the API

```bash
uvicorn app.main:app --reload
```

You should see something like:

```
INFO  traceveil.api :: startup env=local
INFO  uvicorn.error :: Uvicorn running on http://0.0.0.0:8000
```

Now visit:

- **Interactive docs:** <http://localhost:8000/docs> (auto-generated by FastAPI)
- **Liveness:**         <http://localhost:8000/healthz>
- **Readiness:**        <http://localhost:8000/readyz>

If `/readyz` returns `{"status": "ready"}`, the API can reach Postgres
and you're good.

## How the pieces talk

```
       browser / curl
            │  HTTP
            ▼
      ┌─────────────┐
      │  uvicorn    │   web server, hands the request to ↓
      └──────┬──────┘
             │
      ┌──────▼──────┐
      │  FastAPI    │   app/main.py  →  app/routes/*
      └──────┬──────┘
             │  asks for a DB session
      ┌──────▼──────┐
      │  database   │   app/database.py
      └──────┬──────┘
             │  SQL (via asyncpg)
      ┌──────▼──────┐
      │ PostgreSQL  │
      └─────────────┘
```

`app/config.py` is read by all of them at startup — it's the single
source for "what's my DB URL", "what port am I on", etc.

## Adding a feature later (the pattern)

When you're ready to build a real feature (say, an Event store), the
recipe is always the same:

1. Make a folder: `app/modules/events/`
2. Add three files:
   - `models.py` — SQLAlchemy classes that inherit from `Base`
   - `schemas.py` — Pydantic classes for HTTP input/output
   - `router.py` — a `FastAPI APIRouter` with the new endpoints
3. In `app/main.py`, add:
   ```python
   from app.modules.events.router import router as events_router
   app.include_router(events_router)
   ```
4. Restart the server. `init_db()` will create any new tables.

That's the whole extension flow. The foundation doesn't change.

## What's intentionally NOT here

Per the current scope, none of these are implemented yet — each will
become a `modules/<name>/` folder later:

- Authentication (login, JWT)
- Attack simulation engine (the scenario runner)
- Event/AttackSession models
- Replay engine
- WebSocket / realtime streaming
- Detection rules
- Database migrations (Alembic) — we use `Base.metadata.create_all`
  for now, which is fine while there are zero or very few tables.
- Docker / Kubernetes manifests

When you tackle any of these, the foundation above shouldn't need to
change — only new files get added.
